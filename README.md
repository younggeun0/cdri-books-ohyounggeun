# CERTICOS BOOKS

CDRI 프론트엔드 사전과제입니다. 카카오 도서 검색 API로 책을 검색하고, 마음에 드는 책을 찜해 두는 웹앱입니다.

## 프로젝트 개요

- **도서 검색.** 전체 검색과 상세검색(제목, 저자명, 출판사)을 지원합니다. 검색 조건은 URL(`/?query=...&target=...`)에 남아서 새로고침, 뒤로가기, 링크 공유가 그대로 동작합니다.
- **검색 기록.** 최근 검색어 8개를 저장합니다. 검색창을 누르면 목록이 열리고, 방향키로 고르거나 지울 수 있습니다.
- **결과 목록.** 한 페이지에 10권을 보여 주고, 스크롤이 끝에 닿으면 다음 페이지를 불러옵니다. 행을 펼치면 표지, 책 소개, 원가와 할인가, 구매 링크가 보입니다.
- **찜.** 하트를 누르면 찜 목록에 들어갑니다. **내가 찜한 책** 화면에서 모아 보고, 찜을 해제해도 그 화면을 떠나기 전까지는 행이 남아 있어 실수로 눌렀을 때 바로 되돌릴 수 있습니다.
- **반응형.** PC 시안을 기준으로 구현하고, 1024px 미만에서는 목록 항목을 세로로 쌓습니다.

기술 스택은 Next.js 16(App Router, Cache Components), React 19, TypeScript, TanStack Query, Tailwind CSS v4입니다.

## 실행 방법 및 환경 설정

필요한 도구는 Node.js 22 이상과 pnpm 11입니다. pnpm 버전은 `package.json`의 `packageManager`에 고정되어 있어서, Corepack을 켜 두면 맞는 버전이 자동으로 쓰입니다.

1. 의존성을 설치합니다.

   ```bash
   pnpm install
   ```

2. `.env.example`을 복사해 `.env`를 만들고 카카오 REST API 키를 넣습니다. 키는 [카카오 디벨로퍼스](https://developers.kakao.com/)의 **내 애플리케이션 > 앱 키 > REST API 키**에서 확인합니다.

   ```bash
   cp .env.example .env
   # KAKAO_REST_API_KEY=발급받은_키
   ```

   키는 서버(Route Handler와 서버 컴포넌트)에서만 읽습니다. 브라우저 번들에 들어가지 않도록 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.

3. 개발 서버를 실행하고 http://localhost:3000 을 엽니다.

   ```bash
   pnpm dev
   ```

| 명령                        | 하는 일                            |
| --------------------------- | ---------------------------------- |
| `pnpm dev`                  | 개발 서버 실행                     |
| `pnpm build` / `pnpm start` | 프로덕션 빌드와 실행               |
| `pnpm test`                 | Vitest 단위 테스트                 |
| `pnpm lint`                 | ESLint                             |
| `pnpm typecheck`            | 라우트 타입 생성 후 `tsc --noEmit` |
| `pnpm format:check`         | Prettier 검사                      |

GitHub Actions(`.github/workflows/ci.yml`)가 PR마다 install, lint, typecheck, format:check, test, build를 순서대로 실행합니다.

## 폴더 구조 및 주요 코드 설명

```text
src/
├── app/                      # 라우트. 화면 조립과 서버 경계만 둔다
│   ├── page.tsx              # 검색 화면. 직접 접속하면 서버에서 첫 페이지를 미리 불러온다
│   ├── wishlist/page.tsx     # 찜 화면
│   ├── api/books/route.ts    # GET /api/books. 브라우저의 카카오 프록시
│   ├── layout.tsx, providers.tsx, globals.css
├── entities/
│   └── book.ts               # Book 도메인 타입과 카카오 응답 변환
├── features/
│   ├── book-search/          # 검색 조건(URL), 검색 조회, 검색창, 상세검색
│   ├── book-list/            # 가상화 목록, 목록 항목, 무한 스크롤, 가격 표시 규칙
│   ├── search-history/       # 검색 기록 저장
│   └── wishlist/             # 찜 저장과 찜 화면
├── components/               # 기능에 묶이지 않는 UI(Button, Header 등)
├── lib/
│   ├── kakao/                # 카카오 API 호출과 응답 스키마. 서버 전용
│   ├── cn.ts                 # Tailwind 클래스 병합
│   ├── validated-storage.ts  # 읽을 때 검증하는 localStorage 저장소
│   └── use-hydrated.ts
└── test/                     # 테스트용 카카오 응답 데이터
```

의존 방향은 `app → features → entities → lib`입니다. 카카오 응답 모양(`lib/kakao/schema.ts`)은 서버에서 `entities/book.ts`의 `toBookPage`로 한 번만 바뀌고, 화면은 `Book`만 압니다.

### 검색 요청이 화면에 그려지기까지

검색 화면으로 들어오는 길은 두 가지이고, 두 길 모두 같은 TanStack Query 캐시 키(`bookKeys.search`)를 씁니다.

1. **주소로 직접 들어오거나 새로고침할 때.** `app/page.tsx`의 서버 컴포넌트가 URL의 검색 조건으로 카카오를 직접 불러(`features/book-search/server.ts`) 첫 페이지를 캐시에 넣고, `HydrationBoundary`로 브라우저에 넘깁니다. 첫 HTML에 결과가 들어 있어서 로딩 화면 없이 목록이 보입니다.
2. **화면 안에서 검색할 때.** `useBookSearchParams`가 `history.pushState`로 URL만 바꿉니다. 서버를 다시 거치지 않고 `useSearchParams`가 새 조건을 읽으면, `useBookSearch`(`useInfiniteQuery`)가 `/api/books`를 불러 결과를 받습니다. 같은 조건으로 다시 검색하면 기록을 쌓지 않고 결과를 새로 받은 뒤 맨 위로 스크롤합니다.

## 라이브러리 선택 이유

| 라이브러리                               | 쓰는 곳                        | 고른 이유                                                                                                                 |
| ---------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| TanStack Query                           | 검색 조회                      | 무한 조회(`useInfiniteQuery`), 서버 prefetch와 하이드레이션, 상태 코드별 재시도를 직접 만들지 않고 쓸 수 있다             |
| TanStack Virtual                         | 결과 목록                      | 최대 500권이 쌓여도 화면에 보이는 행과 위아래 5개만 DOM에 둔다. 페이지 스크롤을 그대로 쓰는 `useWindowVirtualizer`가 있다 |
| jotai                                    | 찜, 검색 기록                  | `atomWithStorage`가 localStorage 읽기, 쓰기, 다른 탭 동기화를 맡는다. 검증은 `validated-storage.ts`가 끼워 넣는다         |
| zod (`zod/mini`)                         | 카카오 응답, 저장값, 오류 응답 | 스키마 하나로 타입과 검증을 같이 정의한다. 브라우저 번들을 줄이려고 `zod/mini`를 쓴다(첫 로드 JS -5.9%, PR #54)           |
| Tailwind CSS v4                          | 스타일                         | 시안의 색과 글자 크기를 `@theme` 토큰으로 옮겨 `text-title3`, `text-primary`처럼 시안 이름 그대로 쓴다                    |
| class-variance-authority, tailwind-merge | `Button`, `cn`                 | 버튼 변형을 한곳에 정의하고, 호출부 클래스와 충돌하는 클래스는 `cn`이 정리한다                                            |

검토했지만 쓰지 않은 것도 있습니다.

- **Server Actions.** 조회는 Route Handler(`GET /api/books`)로 했습니다. Server Actions는 변경(mutation)용 POST이고 클라이언트마다 순서대로 실행되어, 검색 조회에는 맞지 않습니다.
- **`next/image`.** 카카오 썸네일은 120×174로 이미 작아서 변환 이득이 작습니다. `img`에 `width`, `height`, `loading="lazy"`를 씁니다.
- **IndexedDB.** 책 1,000권을 찜해도 약 0.3MB라 localStorage로 충분합니다. IndexedDB는 비동기라 첫 렌더가 늦어지고 다른 탭 알림도 따로 만들어야 합니다. 수천 권, 오프라인 이미지 저장, 색인 조회가 필요해지면 다시 검토합니다.
- **React Compiler.** 켜 보면 `useWindowVirtualizer`의 결과가 캐시되어 가상 목록이 멈췄습니다. 목록 컴포넌트만 `"use no memo"`로 빼면 동작하지만, 지워지는 수동 메모이제이션은 훅 5개이고 측정한 렌더 수는 줄지 않았습니다. 빌드는 7%, 검색 화면 JS는 1.4% 늘었습니다. 업계에서 흔한 방식은 도입하고 가상화 부분만 빼는 것이라, 코드베이스가 커져서 컴파일러의 혜택을 받는 범위가 넓어지면 도입을 다시 검토합니다. 그때는 virtualizer 호출부만 컴파일에서 빼고, 컴파일된 상태로 스크롤을 검증하는 e2e 테스트를 같이 둡니다.

## 강조 하고 싶은 기능

### 첫 화면부터 결과가 보이는 검색

검색 결과 주소로 들어오면 서버가 첫 페이지를 미리 불러 HTML에 담습니다. 화면 안에서 다시 검색할 때는 `pushState`로 URL만 바꾸고 브라우저에서 조회해서 서버 왕복이 없습니다. 처음에는 `router.push`로 서버를 거치게 했는데, 서버가 카카오를 기다리는 동안 화면이 반응하지 않아(로컬 145→363ms) 이 방식으로 바꿨습니다. 검색창과 결과를 서로 다른 Suspense 경계로 나눠, 결과를 기다리는 동안에도 검색창은 바로 쓸 수 있습니다.

검색 조건은 URL 하나에만 있습니다. 전체 검색과 상세검색은 `target` 값 하나로 구분해서 두 검색 상태가 어긋날 수 없습니다. 사람이 URL을 고쳐도 `parseSearchParams`가 빈 검색어나 모르는 `target`을 정리하고, `/api/books`가 한 번 더 검사합니다.

### 실패를 나눠서 다루는 조회

카카오가 멈추면 3초 뒤에 요청을 끊고(504) 오류 화면을 보여 줍니다. 요청 제한(429)은 `Retry-After`를 따라 기다렸다가 다시 시도하고, 8초보다 길면 기다리지 않고 바로 알립니다. 다음 페이지만 실패하면 받은 목록은 그대로 두고 그 아래에 **다시 시도** 버튼을 보여 주며, 그동안 무한 스크롤은 멈춥니다.

### 믿지 않고 검증하는 데이터

카카오 응답은 서버에서 zod로 검증합니다. 변환이 읽는 필드만 검사해서, 쓰지 않는 필드가 빠지거나 바뀌어도 오류(502)가 나지 않습니다. 문서에 없는 특이값은 실제 API로 확인해 변환 단계에서 정리합니다.

- 할인가가 없으면 `sale_price`가 -1입니다. 화면에는 `salePrice: null`로 넘깁니다.
- ISBN을 id로 쓰면 500건 중 최대 12건이 겹쳤습니다(같은 책 반복, 같은 ISSN을 쓰는 잡지 호수). `url`은 확인한 경우 모두 고유해서 id로 씁니다.
- 50페이지에서도 `is_end`가 false입니다. 그대로 믿으면 51페이지를 요청하게 되므로 50페이지를 끝으로 처리하고, 범위 밖 `page`는 400으로 거절합니다. 50으로 맞춰 주면 같은 책이 끝없이 덧붙습니다.

카카오 API 키 오류(401, 403)는 사용자 잘못이 아니라 서버 설정 문제라 500으로 바꿉니다. 키는 서버에서만 읽고, 빌드 산출물에 키 문자열이 없는 것을 확인했습니다.

localStorage 값도 외부 입력으로 보고 읽을 때 검증해서, 깨진 항목은 버리고 같은 책은 하나만 남깁니다.

### 하이드레이션 전후가 같은 화면

서버는 localStorage를 읽을 수 없어서, 서버 HTML의 하트는 모두 빈 하트입니다. 그대로 두면 찜한 책도 잠깐 빈 하트로 보였습니다(로컬 32ms, 느린 조건 97ms). 하트는 저장소를 읽기 전까지 자리만 남기고 숨깁니다. 찜 화면도 저장소를 읽기 전에는 "찜한 책이 없습니다" 대신 스켈레톤을 보여 줍니다. 목록은 하이드레이션 전에는 일반 흐름으로 그려 서버 HTML과 첫 렌더가 같고, 그 뒤에 가상 목록으로 바뀝니다.

### 많이 쌓여도 가벼운 목록

무한 스크롤로 최대 500권이 쌓여도 화면에 보이는 행과 위아래 5개만 DOM에 둡니다. 가상화 전후로 DOM 노드는 3,662개에서 260~422개로, 다음 페이지가 붙을 때의 작업 시간은 532ms에서 383ms로 줄었습니다. 펼침 상태는 행이 아니라 목록이 들고 있어서, 화면 밖으로 나갔다 돌아온 행도 펼친 채로 보입니다.

### 키보드와 스크린리더

- 검색 기록은 APG combobox 패턴을 따릅니다. 방향키로 고르고, Enter로 검색하고, Delete로 지웁니다.
- 상세검색의 조건 선택은 select-only combobox입니다.
- 상세검색 팝업은 비모달 dialog라 포커스를 가두지 않습니다(APG 기준, 가두는 것은 모달 dialog). 열면 입력창으로 포커스를 옮기고, Esc를 누르면 상세검색 버튼으로 돌려보내고, 바깥을 누르거나 포커스가 밖으로 나가면 닫힙니다.
- 결과 수(`총 N건`)는 `aria-live` 영역이라 검색이 끝나면 스크린리더가 읽어 줍니다.
- 가상화로 화면 밖 행이 DOM에 없어도 `aria-setsize`와 `aria-posinset`으로 전체 개수와 순서를 알립니다.
- OS의 동작 줄이기 설정을 켜면 스켈레톤과 스피너가 움직이지 않습니다.

### 찜 화면의 되돌리기

찜 화면은 들어온 순간의 목록을 복사해 행으로 보여 줍니다. 하트를 눌러 해제해도 결과 수만 줄고 행은 남아서, 다시 누르면 바로 되돌릴 수 있습니다. Cache Components는 페이지를 이동해도 이 화면을 언마운트하지 않고 숨기기 때문에, 숨겨질 때 복사본을 비우고 다시 보일 때 새로 만듭니다.

## 알려진 한계와 협의할 점

### 기획과 협의할 점

- **검색 결과 500권 상한.** 카카오 API는 `page`를 50까지만 받습니다. 한 페이지 10권 기준으로 500권이 끝이라, `총 864건`으로 보여도 500권까지만 스크롤됩니다. 시안에는 건수 제한이 없어서 표시 방식(예: "500권까지 표시")을 정해야 합니다.
- **찜과 검색 기록의 저장 위치.** 지금은 브라우저 localStorage에만 저장해서 기기나 브라우저가 바뀌면 사라집니다. 찜은 로그인과 서버 저장이 맞다고 봅니다.

### 디자인팀과 소통할 점

시안대로 구현하면서 생긴 것들입니다.

- **임의 px 값.** 시안 수치가 간격과 크기 토큰이 아니라 개별 px 값이라 코드에 `w-[115px]`, `xl:ml-[400px]` 같은 임의값이 흩어져 있습니다. 간격과 크기 토큰을 합의하면 줄일 수 있습니다.
- **색 대비.** 보조 글자색(`#8d94a0` 등)이 흰 배경에서 WCAG AA 기준(4.5:1)에 못 미칩니다.
- **표지 해상도.** 카카오 썸네일 원본이 120×174라 상세보기(PC 210×280)에서는 확대되어 흐립니다.
- **모바일 프레임.** 시안에 모바일 화면이 없어서 1024px 미만 배치는 PC 시안의 요소를 세로로 쌓아 정했습니다.

### 기술적 한계

- **모바일 행 높이.** 320~375px 폭에서는 긴 제목이 두 줄이 되어 행 높이가 187px과 161px로 섞입니다. 하이드레이션 직후 가상 목록이 추정 높이로 한 프레임 그려져 CLS 0.0073이 생깁니다(기준 0.1). 제목 자리를 두 줄로 고정하면 사라지지만 짧은 제목에 빈 줄이 생겨서 그대로 둡니다.
- **가상화와 브라우저 검색.** 화면 밖 행은 DOM에 없어서 Ctrl+F로 찾을 수 없습니다. 포커스가 있던 행이 화면 밖으로 나가면 포커스도 사라집니다.
- **서버 캐시와 요청 제한.** `/api/books`에는 서버 캐시가 없어서 같은 검색도 매번 카카오를 호출합니다. 브라우저의 TanStack Query 캐시(60초)만 있습니다. 프록시를 통한 카카오 쿼터 소진을 막는 장치도 없습니다.
- **서버의 카카오 요청 취소.** 사용자가 검색어를 바꾸면 브라우저 요청은 취소되지만, 서버에서 카카오로 가는 요청은 3초 제한 시간까지 계속됩니다.
- **저장 실패 알림.** 용량 초과나 시크릿 모드로 localStorage 저장이 실패해도 그 탭에서는 계속 동작하지만, 사용자에게 알리지 않고 새로고침하면 사라집니다. 두 탭에서 동시에 찜을 바꾸면 나중에 쓴 쪽이 남습니다.
- **검색 기록 삭제 안내.** 기록 옆 X는 마우스용이고, 키보드는 Delete 키로 지웁니다. 이 키를 화면에서 안내하지 않습니다.
- **빌드의 Google Fonts 의존.** `next/font`가 빌드할 때 Noto Sans KR을 내려받습니다. 네트워크가 실패하면 빌드가 실패합니다(CI에서 1번 있었고 재실행으로 통과).

## 개발 과정

모든 작업은 GitHub 이슈를 먼저 만들고, 그 이슈를 닫는 PR을 머지하는 순서로 진행했습니다. 각 PR 본문과 코멘트에 AI 사용 기록(맡긴 일, 채택하거나 거절한 제안과 이유, 토큰 사용량)을 남겼습니다.

구현을 마친 뒤 요청이 들어와 화면에 그려지기까지의 순서(API 경계, 도메인 변환, 서버 상태, URL 상태, 브라우저 저장, UI 컴포넌트, 화면 상태, 스타일과 성능)로 코드를 다시 리뷰하고, 그때 나온 개선을 같은 흐름의 PR로 반영했습니다. 측정이나 사례 조사로 결정한 것(실측 결과를 근거로 한 기각 포함)은 해당 이슈와 PR에 근거를 남겼습니다.

테스트는 Vitest로 화면과 분리한 순수 로직을 검증합니다. 대상은 카카오 변환, 재시도 정책, URL 해석, 검색 기록과 찜 규칙, 가격 표시, 저장소 검증, Route Handler 입력 검사입니다.
